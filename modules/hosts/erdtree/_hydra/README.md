# Erdtree CI and cache cutover

Hydra serves signed paths from erdtree's local Nix store. Celler keeps its SQLite database, tokens, cache signing key, and B2 storage on siofra. The endpoints are `hydraUrl` and `cellerUrl` in `dotfiles-secrets/domains.nix`. Both web services bind to loopback and use Tailscale Serve, not Funnel. Hydra substitutes directly from Celler and `cache.nixos.org`, never from its own cache. Reuse the existing CI signing key and ARM builder key; the legacy filenames in `dotfiles-secrets` are still in use, as are the restic credentials.

Treat access to Hydra as access to erdtree's Nix store, including build inputs, logs, and other valid paths, not just published CI jobs. Restrict the Hydra endpoint to trusted clients in the tailnet policy. Restrict the Celler endpoint to the intended Celler clients, and allow erdtree to reach the ARM builder's SSH port. Keep Celler's B2 bucket private: authorized downloads may get short-lived signed B2 redirects, which are bearer URLs, not public cache access. Never put plaintext secrets in the Nix store.

## Switch order

Publish the endpoint configuration in the private `dotfiles-secrets` repository first, then run `nix flake update dotfiles-secrets` here to pin that revision. For local verification before publishing, use `--override-input dotfiles-secrets "git+file://$HOME/dotfiles-secrets" --no-write-lock-file`.

1. From the old configuration, take a final Garnix PostgreSQL/restic backup. Check for workflows, artifacts, deploy URLs, and required forge checks on any other enrolled repos. Dotfiles `main` has no required GitHub checks as of the cutover review.
2. Switch elphael before erdtree. New and old Celler URLs do not overlap; coordinate the siofra switch and roll out consumers promptly. A client on the wrong side of that switch may temporarily miss Celler. Update other consumers, including torrent (with Tailscale connected). The next activation adapts the existing encrypted netrc to the new hostname without changing the token. If erdtree cannot be built through the normal route, use `just build-to-erdtree-skip-cache` from an x86 Linux machine; it builds locally using only `cache.nixos.org` and copies over SSH.
3. Switch farum-azula before erdtree. Hydra uses the legacy `nix-store --serve --write` protocol for its ARM worker, not Garnix's `ssh-ng` daemon protocol. During this interval the old Garnix ARM route may stop working.
4. Build the new erdtree closure before activating it. The first build may compile Hydra and its dependencies. Then switch erdtree once. It stops the Garnix services, leaves their state on disk, and starts Hydra with a new local PostgreSQL database in the existing PostgreSQL 18 cluster. If the old guest route is still advertised, run `sudo tailscale set --advertise-routes=` on erdtree (confirm no other advertised routes first) and remove its approval in the tailnet admin console. Remove the retired Garnix and old Celler public DNS/Cloudflare tunnel records and Garnix webhooks after verifying the new endpoints. Do not remove unrelated erdtree or siofra ingress.

## Start CI and verify

- On erdtree, create a local Hydra admin with `sudo -u hydra /run/current-system/sw/bin/hydra-create-user joe --password-prompt --role admin`.
- Using a secret manager, install `/var/lib/hydra/github-nix.conf` owned by `hydra`, mode `0400`, with `access-tokens = github.com=<read token>`. Grant access only to the private flake inputs needed, never print the token, and restart `hydra-evaluator`. Keep jobsets restricted to trusted revisions and do not enroll untrusted forks.
- In Hydra, create a `dotfiles` project and an enabled Flake jobset `main` using `hydraDotfilesFlake` from the private `domains.nix` for the flake URI, with periodic evaluation (for example, every 300 seconds) and a small number of retained successful builds (for example, two). Use a pushed revision containing `hydraJobs`. Trigger an evaluation and check for a real x86 build and a native ARM build. This setup polls; it does not replace any GitHub check reporting or deploy anything automatically.
- Verify both tailnet URLs and confirm the old public URLs and the backends' ports are not accessible from outside the allowed tailnet. Confirm Celler rejects a known private NAR request without a token. From a clean client store, realize a Hydra-built path using Hydra and `cache.nixos.org`; ensure the Hydra path is downloaded and signature checks stay enabled. Confirm the Hydra queue runner can substitute a known Celler-only path.
- Verify the new database dump and restic snapshot after the first backup. Keep old state during the rollback window; do not delete the database or buckets as part of host activation. Hydra results stop being downloadable when their paths are garbage-collected. If a low-disk check stops the queue runner or evaluator, free space before restarting the stopped units.
